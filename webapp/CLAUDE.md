# webapp — offline reader, workbench &amp; dataset exporter

Standalone app (web + Android) that turns the `system_prompts_leaks` repo into
an indexed, fully-offline tool for browsing/searching the collection,
comparing prompts side by side, drafting new local prompts from them, and
exporting the collection as JSONL training data.

Stack: React + TypeScript + Vite, wrapped by Capacitor for Android. One Vite
build (`dist/`) is both the static/PWA web app and the payload Capacitor
packages into the Android WebView shell — no backend, no server, everything
runs from data bundled at build time.

## Architecture

```
webapp/
  scripts/
    parse-readme.mjs     README.md table/details-block parser
    build-index.mjs      ingestion pipeline — the source of truth for public/generated/**
    gen-icons.mjs         placeholder PWA icon generator (no image deps)
  src/
    data/index.d.ts       FileEntry / MetadataIndex / VendorContentChunk types
    lib/                   metadata.ts, contentLoader.ts, searchIndex.ts, db.ts, filter.ts, download.ts
    state/                 MetadataContext (eager metadata), SelectionContext (the "working set")
    components/             Layout, FilterBar, PinButton
    features/
      browse/     vendor → subcategory → file tree, filter chips
      search/     MiniSearch-backed full-text search
      viewer/     single document view (raw / rendered markdown toggle)
      compare/    side-by-side workbench, 2-doc line diff
      drafts/     compose/remix editor + reference panel, persisted to IndexedDB
      export/     JSONL dataset exporter (flat or chat-message schema)
  public/
    generated/     BUILD OUTPUT — gitignored, regenerated by build-index.mjs, not committed
    icons/          placeholder PWA icons, committed (see below)
  android/          Capacitor native project — gitignored, regenerated via `npx cap add android`
```

`public/generated/` and `android/` are gitignored and not committed — both
are cheaply and deterministically regenerable (from `../<Vendor>/**` +
`../README.md`, or from `npx cap add android`, respectively), and
`generated/` in particular would just be duplicated, stale-prone content
bytes in git history if committed.

`public/icons/*.png`, by contrast, **are committed**. They're small,
hand-generated placeholder PWA icons (a simple "index" glyph — see
`scripts/gen-icons.mjs`) referenced directly by `vite.config.ts`'s PWA
manifest config; nothing in the build pipeline regenerates them
automatically, so leaving them gitignored would break the manifest's icon
references on a fresh clone. Swap them for real artwork by replacing the
three PNGs (or editing `gen-icons.mjs` and re-running it) whenever branding
is available.

## The indexing pipeline

`scripts/build-index.mjs` is the only place that reads the sibling repo. It:

1. Parses `../README.md` (`scripts/parse-readme.mjs`) into a
   `path → { displayName, featured, recentDate }` map. The README is a
   hand-curated index — a "Recently Updated" table plus one `## Vendor`
   section per vendor, each with a primary table and an optional
   `&lt;details&gt;&lt;summary&gt;` block of older/variant links — and is the richest
   source of canonical names/dates available, better than filenames alone.
   - Link text becomes the display name; if it's generic ("System prompt",
     "Prompt", "Link", …) the row's first cell is used instead. When both
     exist and differ, they're joined as `"Row Label · Link Text"`.
   - External links (`http…`) and directory links (href ending in `/`,
     e.g. `Anthropic/Official/`) are skipped — they don't map to a single file.
   - Paths are `decodeURIComponent`-ed (README uses `%20` for spaces, e.g.
     `Claude%20Code/...`).
2. Walks every top-level directory except dot-directories (`.git`,
   `.github`, `.claude`, …), `webapp`, and `node_modules` (vendor folders
   are auto-discovered, not hardcoded).
   For each file it records `vendor`, `subcategory` (the subfolder chain, or
   `null`), `slug`, `ext`, `size`, `wordCount`, and infers `tags` from the
   filename (variant suffixes like `api`, `thinking`, `instant`, `no-tools`,
   `with-tools`, reasoning-effort levels, personality names — see
   `VARIANT_VOCAB` and the compound-pattern checks at the top of the script).
3. Merges: README data wins for `displayName`/`featured`/`recentDate`; files
   the README doesn't (yet) link to fall back to a humanized filename and
   `featured: false`.
4. Emits, into `public/generated/`:
   - `metadata.json` — full `FileEntry[]` + per-vendor summaries. Small, eager-loaded on app start.
   - `content/&lt;vendor-lowercase&gt;.json` — `{ path: rawText }` per vendor. Fetched lazily, one vendor at a time, and cached — see `src/lib/contentLoader.ts`.
   - `search-index.json` — a MiniSearch index built over displayName/vendor/subcategory/tags/content (boosted toward name/tags), serialized via `toJSON()` and reloaded client-side with `MiniSearch.loadJSON()` in `src/lib/searchIndex.ts`. The field/boost config in that file **must** mirror the one in `build-index.mjs` — MiniSearch needs matching config to deserialize a prebuilt index.
5. Validates: warns (does not fail) on README links that don't resolve to a
   file on disk, and on files that exist but aren't yet linked from the
   README. **This has already caught real drift in the source repo** — e.g.
   the README's "Codex (older)" section links to `OpenAI/Codex/gpt-5.md` etc.,
   but those files have since moved to `OpenAI/Codex/old/gpt-5.md`. That's
   expected, not a bug in the script; the console warnings tell you exactly
   what's stale.

### Rebuilding the index

```
npm run build:index      # standalone — writes public/generated/**
```

This also runs automatically before `npm run dev` and `npm run build` (via
the `predev`/`prebuild` npm scripts), so the app always reflects whatever is
currently on disk in the sibling content folders — no manual step needed in
normal development.

To add a new filename-variant tag, edit `VARIANT_VOCAB` (single-token tags)
or the compound-pattern checks (e.g. the `no-tools` / `with-tools` handling)
near the top of `scripts/build-index.mjs`.

### Search index size/content-mode tuning

By default the MiniSearch index embeds full document text (`INDEX_CONTENT_MODE`
unset or `full`), so `search-index.json` ends up roughly as large as the
content itself (~2.5MB serialized for this repo's ~9.5MB of source text).
If that proves too slow to parse on low-end Android devices, set:

```
INDEX_CONTENT_MODE=snippet npm run build:index
```

which indexes only the first ~200 words per file instead of the full text —
smaller/faster index, at the cost of not full-text-matching deep in long
documents (the viewer's own text is unaffected either way; this only changes
what `search()` can match against).

## Running it

**Web:**
```
npm install
npm run dev              # local dev server, index rebuilt automatically
npm run build             # production build → dist/
npm run preview            # serve dist/ locally to smoke-test the prod build
```

**Android (via Capacitor):**
```
npx cap init                   # one-time — already committed as capacitor.config.ts
npx cap add android            # regenerates android/ from scratch (gitignored)
npm run cap:sync                # = npm run build && npx cap sync android
npx cap open android            # opens the project in Android Studio
```

Everything through "`android/` project scaffolded and synced with the latest
web build" is verifiable without an Android SDK — `cap add`/`cap sync` just
copy files and edit Gradle config. **Actually compiling an APK
(`./gradlew assembleDebug` / `assembleRelease`, or `npx cap run android`)
requires a real Android SDK** (`ANDROID_HOME` + `sdkmanager`) to resolve the
Android Gradle Plugin and platform artifacts from Google's Maven repo — this
is not available in every environment (in particular, sandboxed CI-style
containers without SDK licenses accepted). Do that step on a machine with
Android Studio installed, or in a CI job that runs
`android-actions/setup-android` (or equivalent) before `./gradlew
assembleDebug`. On-device verification of IndexedDB persistence and the
export download/share flow inside the real Android WebView should also
happen there — WebView download handling is the one area most likely to
diverge from desktop browser behavior; if `Blob` + `&lt;a download&gt;` proves
unreliable on-device, add `@capacitor/filesystem` + `@capacitor/share` as a
native fallback for the export feature.

## Known data-shape caveats

- Not every file on disk is linked from the README (currently ~105 files —
  mostly `Anthropic/Claude Code/bundled-skills/**` and
  `Anthropic/Official/**` dated snapshots, which are only ever linked via a
  directory link like `Anthropic/Official/`, not per-file). Those get a
  humanized-filename `displayName` and `featured: false`.
- A handful of README links are currently stale (point at files that have
  moved or been renamed since — e.g. several `OpenAI/Codex/*` "older"
  entries, `Mistral/le-chat.md`). `build-index.mjs` warns about these on
  every run; it's a signal to fix the README, not something the app needs to
  work around.
- Non-markdown content: `.txt`, `.json` (e.g. a Gemini tool schema), `.xml`
  (a 110KB tool-augmented Claude 3.7 prompt), `.js`/`.py` (bundled Claude
  Code skill scripts) are all indexed like any other file. The viewer
  pretty-prints `.json`, and renders everything else as monospaced raw text.

## Verification checklist

Runnable anywhere (no Android SDK needed):
- `npm run build:index` — check the console summary (file/vendor counts,
  warnings) matches expectations.
- `npx tsc -b` — type-checks clean.
- `npm run build` — production build succeeds.
- `npm run dev` / `npm run preview` — manually exercise: browse tree renders
  and filters, search returns results, a document opens and copy/download
  work, pinning two docs and opening Compare shows both (and the line diff
  toggle for exactly 2), a draft saves and survives a reload (IndexedDB),
  Export produces a valid `.jsonl` (every line parses as JSON).
- Offline: load the built app once online, then go offline (e.g. DevTools'
  "Offline" throttling, or `browserContext.setOffline(true)` in a Playwright
  script) and confirm browse/search/viewer/export still work from the
  service worker's precache.
- `npx cap add android` / `npx cap sync android` complete without error.

Needs a real Android SDK / device (not verifiable in a plain Node
environment): `./gradlew assembleDebug`/`assembleRelease`, installing and
running the APK, and on-device checks of offline behavior, IndexedDB, and
the export download/share flow in the Android WebView.

## Known gaps and quirks

- **`lib/db.ts` collections API is unused.** `listCollections` /
  `saveCollection` / `deleteCollection` and the `collections` IndexedDB
  store exist but no UI calls them — the intended "saved sets of doc paths
  feeding Compare/Export" feature was never wired up. Either build that UI
  or trim the API; don't let it drift.
- **13 stale README links** (files that moved to `OpenAI/Codex/old/`,
  `Mistral/le-chat.md`, …) — build warns on every run. Fixing the repo
  README upstream would silence these; the app is unaffected.
- **~105 files aren't linked from README** (bundled-skills, dated Official
  snapshots) and use humanized-filename display names. Expected.
- **Search index is ~2.5MB serialized** (full-content mode). Fine on
  desktop; if first-search parse time on low-end Android is a problem, use
  `INDEX_CONTENT_MODE=snippet` (documented above).
- **The APK has still never been compiled** — no Android SDK in the dev
  sandbox. The Capacitor project scaffolds/syncs clean, but the true
  handoff (Gradle build + on-device WebView checks, especially the export
  Blob-download flow) hasn't happened anywhere yet.
